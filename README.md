# Savana3D — دليل التشغيل

هذا المشروع نسخة أولية (MVP) شغّالة فعليًا، فيها:
- تسجيل دخول وإنشاء حساب بثلاثة أدوار (زبون، مصمم، صاحب طابعة)
- متجر لعرض التصاميم
- رفع تصاميم (للمصمم)
- نظام طلبات كامل (طلب → قبول → طباعة → شحن → استلام)
- لوحة تحكم مختلفة حسب نوع الحساب

---

## الخطوة 1: تجهيز حساب Supabase (قاعدة البيانات + التخزين + تسجيل الدخول) — مجاني

1. روح على https://supabase.com وسجّل حساب مجاني.
2. اضغط **New Project**، واختر اسم ومنطقة قريبة منك (مثل Frankfurt أو Singapore).
3. بعد ما يجهز المشروع (يأخذ دقيقة أو دقيقتين)، روح لتبويب **SQL Editor** من القائمة الجانبية.
4. افتح ملف `supabase/schema.sql` الموجود بهذا المشروع، انسخ كل محتواه، والصقه في محرر SQL بموقع Supabase.
5. اضغط **Run**. هذا هيسوي لك:
   - جدول المستخدمين (profiles)
   - جدول التصاميم (designs)
   - جدول الطلبات (orders)
   - كل قواعد الحماية (Row Level Security)
   - مساحات تخزين الملفات (Storage buckets)

---

## الخطوة 2: ربط المشروع بمفاتيح Supabase

1. من داخل مشروع Supabase، روح لـ **Project Settings** (⚙️) → **API**.
2. راح تشوف قيمتين تحتاجهم:
   - **Project URL**
   - **anon public key**
3. انسخ ملف `.env.local.example` وسمّه `.env.local`:
   ```bash
   cp .env.local.example .env.local
   ```
4. افتح `.env.local` وحط القيم اللي نسختها:
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
   ```

---

## الخطوة 3: تشغيل المشروع على جهازك

تحتاج **Node.js** مثبت على جهازك (نسخة 18 أو أحدث). إذا ما عندك، حمّله من https://nodejs.org

```bash
# داخل مجلد المشروع
npm install
npm run dev
```

بعدها افتح المتصفح على: `http://localhost:3000`

---

## الخطوة 4: تجربة المشروع

1. اضغط **إنشاء حساب** وسجّل 3 حسابات تجريبية بأدوار مختلفة (زبون، مصمم، طابع) — استخدم إيميلات وهمية مختلفة لكل واحد (مثل `test1@test.com`، `test2@test.com`).
2. سجّل دخول بحساب **المصمم** وارفع تصميم من صفحة "رفع تصميم".
3. سجّل خروج، وسجّل دخول بحساب **الزبون**، روح للمتجر، واطلب طباعة التصميم.
4. سجّل خروج، وسجّل دخول بحساب **الطابع**، روح للوحتي، بتلقى الطلب الجديد وتقدر تقبله وتحدّث حالته خطوة بخطوة.

---

## الخطوة 5: تفعيل الدفع عبر Moyasar (بوابة سعودية معتمدة تدعم مدى)

> ⚠️ لماذا Moyasar ومو Stripe؟ لأن Stripe غير مدعوم رسميًا للأعمال المسجّلة بالسعودية، وما يدعم شبكة مدى أصلًا. Moyasar بوابة سعودية معتمدة من مؤسسة النقد (ساما)، وتدعم مدى + فيزا/ماستركارد + Apple Pay.

1. روح على https://moyasar.com وسجّل حساب.
2. من لوحة التحكم، فعّل **الوضع التجريبي (Sandbox)** أول عشان تختبر بدون فلوس حقيقية.
3. روح لـ **Settings → API Keys**، وانسخ:
   - **Publishable Key** (يبدأ بـ `pk_test_`) — آمن يظهر بالمتصفح
   - **Secret Key** (يبدأ بـ `sk_test_`) — سري تمامًا، للسيرفر فقط
4. حطهم في `.env.local`:
   ```
   NEXT_PUBLIC_MOYASAR_PUBLISHABLE_KEY=pk_test_xxxxxxxxxxxxx
   MOYASAR_SECRET_KEY=sk_test_xxxxxxxxxxxxx
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```
5. عبّي بقية القيم:
   ```
   SUPABASE_SERVICE_ROLE_KEY=  ← من Supabase: Project Settings → API → service_role
   ```

   ⚠️ **تحذير مهم**: `SUPABASE_SERVICE_ROLE_KEY` مفتاح خطير جدًا — يتجاوز كل حماية البيانات. لا تحطه أبدًا في كود يشتغل بالمتصفح، ولا ترفعه على GitHub. موجود فقط داخل `pages/api/` (كود سيرفر).

6. **شغّل تحديثات قاعدة البيانات بالترتيب** (كلها بمحرر SQL في Supabase):
   - `supabase/schema.sql` (لو أول مرة)
   - `supabase/migration_shipping_payment.sql`
   - `supabase/migration_moyasar.sql`
   - `supabase/migration_signup_trigger.sql` (**ضروري**: يصلح مشكلة فشل التسجيل عند تفعيل تأكيد الإيميل)

## تفعيل تأكيد الإيميل (اختياري لكن موصى به)

1. افتح حساب مجاني على **resend.com**، خذ مفتاح الـ API من API Keys
2. بـ Supabase: **Authentication → Emails → SMTP Settings**، فعّل Enable custom SMTP وعبّي:
   - Sender email: `onboarding@resend.dev`
   - Sender name: `Savana3D`
   - Host: `smtp.resend.com` / Port: `465` / Username: `resend` / Password: مفتاح Resend
3. فعّل **"Confirm email"** من **Authentication → Settings**

7. **للدفع التجريبي**، استخدم بطاقة Moyasar الوهمية:
   - رقم البطاقة: `4111 1111 1111 1111`
   - أي تاريخ انتهاء مستقبلي، وأي CVC

8. **لما تكون جاهز للانطلاق الفعلي**: ارجع لـ Moyasar Dashboard واطلب تفعيل الحساب الحقيقي (Live) — بيطلبون منك معلومات نشاطك التجاري (سجل تجاري إن وجد، معلومات المنتج)، وبعد الموافقة تستبدل مفاتيح `pk_test_`/`sk_test_` بمفاتيح `pk_live_`/`sk_live_`.

---

## كيف صار يشتغل نظام الطلب الآن (بعد إضافة الشحن والدفع)

1. الزبون يضغط "اطلب طباعة" → يعبّي بيانات الشحن (الاسم، الجوال، المدينة، العنوان).
2. يُنشأ الطلب بحالة **"بانتظار الدفع"**.
3. يظهر نموذج دفع Moyasar مباشرة بنفس الصفحة (يدعم مدى وفيزا وماستركارد).
4. بعد الدفع، يتحوّل الزبون لصفحة تأكيد، والسيرفر يتحقق من صحة عملية الدفع مباشرة مع Moyasar (مو بس يثق بالمتصفح).
5. بس بعد التأكيد الفعلي، تتغيّر حالة الطلب لـ **"بانتظار طابع"** ويصير مرئي لأصحاب الطابعات — يعني ما فيه طلبات وهمية غير مدفوعة توصل للطابعين.
6. الطابع يقبل، يطبع، ويدخل **رقم تتبع الشحنة** لما يشحن.
7. الزبون يشوف رقم التتبع مباشرة من لوحته.

---



## الخطوة 7: رفع المشروع على GitHub (بدون Replit)

1. افتح حساب مجاني على **github.com**
2. اضغط **"+" → "New repository"**، سمّه `savana3d`، واخترها **Private** أو **Public** (حسب رغبتك)، ثم **Create repository**
3. بصفحة المستودع الفاضي، دوّر على رابط أو زر يقول **"uploading an existing file"**
4. فك ضغط ملف `savana3d.zip` بجهازك أو جوالك (يوجد تطبيقات فك ضغط مجانية للجوال)
5. اسحب/ارفع **كل الملفات والمجلدات** (بدون مجلد `node_modules` أو `.next` إن وجدا — أصلًا محذوفين من النسخة المسلَّمة لك)
6. اكتب أي رسالة بخانة "Commit changes" واضغط **"Commit changes"**

## الخطوة 8: النشر على Vercel (رابط حقيقي يشتغل لأي زائر)

1. روح على https://vercel.com وسجّل دخول بحساب GitHub
2. اضغط **"Add New..." → "Project"**، واختر مستودع `savana3d` من القائمة، ثم **Import**
3. في قسم **Environment Variables**، أضف كل هذي القيم (كل وحدة بسطر: Key و Value):
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `NEXT_PUBLIC_MOYASAR_PUBLISHABLE_KEY`
   - `MOYASAR_SECRET_KEY`
   - `NEXT_PUBLIC_SITE_URL` (اتركها فاضية الحين)
4. اضغط **Deploy**. بعد دقيقة أو دقيقتين بيصير عندك رابط حقيقي مثل:
   `https://savana3d.vercel.app`
5. ارجع لإعدادات المشروع بـ Vercel → **Settings → Environment Variables**، وحدّث `NEXT_PUBLIC_SITE_URL` بنفس الرابط الجديد (بدون `/` بالنهاية)
6. روح لتبويب **Deployments** واضغط **"Redeploy"** على آخر نسخة عشان يفعّل التحديث

## تحديث الكود لاحقًا

أي تعديل بعدين، تقدر تسويه مباشرة من محرر الملفات بموقع GitHub نفسه (افتح الملف، اضغط ✏️، عدّل، احفظ) — Vercel يكتشف التغيير وينشر نسخة جديدة تلقائيًا، بدون ما تحتاج Replit إطلاقًا.

## هيكل المشروع

```
pages/
  index.js                        → الصفحة الرئيسية
  login.js                        → تسجيل الدخول
  signup.js                       → إنشاء حساب (يختار المستخدم دوره)
  upload.js                       → رفع تصميم (للمصمم فقط)
  dashboard.js                    → لوحة تحكم مختلفة حسب الدور
  order-success.js                → صفحة تأكيد بعد الدفع + التحقق من صحته
  store/index.js                  → عرض كل التصاميم
  store/[id].js                   → تفاصيل تصميم، بيانات الشحن، ونموذج الدفع
  api/verify-payment.js           → يتحقق من صحة عملية الدفع مع Moyasar
lib/
  supabaseClient.js                → الاتصال بـ Supabase (من المتصفح)
  supabaseAdmin.js                 → اتصال بصلاحيات كاملة (من السيرفر فقط)
  useAuth.js                       → معرفة المستخدم الحالي ودوره
components/
  Navbar.js                        → شريط التنقل العلوي
supabase/
  schema.sql                       → قاعدة البيانات الأساسية
  migration_shipping_payment.sql   → تحديث الشحن وطرق الدفع
  migration_moyasar.sql            → تحديث خاص بربط Moyasar
  migration_signup_trigger.sql     → إصلاح مشكلة التسجيل مع تأكيد الإيميل
public/
  logo.svg                         → أيقونة الشعار (Navbar، Favicon)
  logo-lockup.svg                  → الشعار الكامل مع الاسم (الصفحة الرئيسية)
```

## الميزات اللي تقدر تضيفها لاحقًا

- معاينة التصميم ثلاثي الأبعاد داخل المتصفح (Three.js أو model-viewer)
- تقسيم الدفع تلقائيًا بين المصمم/الطابع/المنصة (يحتاج Stripe Connect)
- تكلفة شحن ديناميكية حسب المدينة أو الوزن بدل الرسم الثابت
- توزيع تلقائي للطلبات على أقرب طابع بدل عرضها للجميع
- نظام تقييمات للطابعين والمصممين
- إشعارات فورية بالبريد أو الجوال عند تغيّر حالة الطلب
- تتبع شحن حي عبر ربط API شركة الشحن

كل وحدة من هذي تقدر تُبنى فوق نفس الأساس الموجود بالمشروع.
